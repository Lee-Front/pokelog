# Pokemon Variant Model

Generated: 2026-04-13

## Purpose

This document records the first runtime-ready variant layer.

The goal is to separate:

- base species
- permanent world variants
- battle-only forms

without forcing those forms back into `species.json`.

## Current Runtime Scope

The project now has a dedicated static variant store:

- `data/pokemon/variants.json`

This file is generated from:

- `data/pokemon/art-species-split.json`

The runtime loader now exposes:

- `getVariants()`
- `getVariantById(id)`
- `getVariantsByBaseSpecies(baseSpecies)`

`OwnedPokemon` also now reserves:

- `variantId?: string | null`

Current runtime status:

- base species still remain the canonical encounter and egg identities
- variants are now loaded as a separate table
- owned Pokemon can now reserve a variant identity without schema churn later
- encounter, egg, and evolution flows do not yet actively instantiate non-null `variantId` values

## Variant Schema

Current runtime shape:

```ts
type VariantKind = "regional" | "permanent-form" | "battle-form";

interface VariantData {
  id: string;
  baseSpecies: string;
  kind: VariantKind;
  name: string;
  category: string;
  sourceArtSlug: string;
  formSuffix: string;
  encounterEligible: boolean;
  eggEligible: boolean;
  typing?: string[];
  baseStatsOverride?: Partial<SpeciesData["baseStats"]>;
  learnsetOverride?: Partial<SpeciesLearnset>;
}
```

## Current Kind Mapping

The generator currently maps art-split categories like this:

- `regional`, `regional-special` -> `regional`
- `mega`, `gigantamax`, `primal`, `rider`, `battle-form` -> `battle-form`
- everything else in `specialForms` -> `permanent-form`

Examples:

- `vulpix-alola` -> `regional`
- `rotom-heat` -> `permanent-form`
- `charizard-mega-x` -> `battle-form`

## Eligibility Policy

The first runtime version uses conservative flags:

- `battle-form` variants are never encounter-eligible
- `battle-form` variants are never egg-eligible
- `regional` and `permanent-form` variants are marked encounter-eligible
- `regional` variants are marked egg-eligible (59 variants)
- `permanent-form` and `battle-form` variants remain egg-ineligible

Note on egg eligibility:

- the egg-gacha runtime currently queries base species only (via `getSpecies()`)
- variant `eggEligible` flags are reserved for future use when the egg loop is extended to include variant species
- regional variants are flagged as egg-eligible in data to prepare for this extension

## Current Limitations

- The generator is art-split driven, not PokeAPI-form driven.
- `typing`, `baseStatsOverride`, and `learnsetOverride` are reserved but not populated yet.
- Variant encounter flags exist, but region pools still reference base species only.
- `targetVariantId` exists in evolution branches, but no runtime branch currently resolves into a populated variant target.
- `variantId` is reserved on owned Pokemon, but no gameplay loop writes it yet.

## Recommended Next Work

1. Decide which regional variants should become actual encounter entries in region data.
2. Populate override fields for runtime-significant variants such as regional forms.
3. Add `targetVariantId` support to evolution resolution when a branch should land on a non-default variant.
4. Decide whether pattern/cosmetic forms should stay data-only or become explicit unlock systems.
